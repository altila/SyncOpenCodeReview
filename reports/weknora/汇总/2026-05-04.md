#### 劣势/风险
1.  **LocalStorage 膨胀风险**：虽然按用户隔离了偏好，但代码中未见对过期用户配置的清理机制。如果一台机器上有大量用户轮流登录，`localStorage` 可能会堆积大量 `WeKnora_${userId}_*` 键值。
2.  **字体缩放的布局挑战**：引入 `var(--app-font-scale)` 后，虽然字体大小会改变，但如果部分容器硬编码了 `height` 而非 `min-height`，可能会出现文字溢出或布局错位。建议对关键 UI 路径进行大字体模式下的回归测试。
3.  **正则匹配的脆弱性**：`security.ts` 中使用了复杂的正则表达式来保护图片路径（`protectProviderImageSrcInHTML`）。随着支持的 Provider（如新增的 `ks3`）增多，正则维护成本变高，且容易因特殊字符处理不当导致 XSS 绕过或匹配失效。
4.  **同步阻塞风险**：`migratePreferencesIntoUser` 在模块加载时运行，虽然 `localStorage` 操作很快，但在极端情况下（如存储损坏或 quota 满），`try-catch` 虽然捕获了错误，但控制台的 `console.warn` 可能会在生产环境下暴露过多内部逻辑。

**建议**：
*   考虑为 `preferenceStorage` 增加一个简单的 LRU 清理逻辑，删除 30 天未登录用户的本地配置。
*   针对 Wiki 提示词中的“去重检查”，建议在后端 API 层也增加相应的逻辑校验，而非完全依赖 AI 的提示词约束。

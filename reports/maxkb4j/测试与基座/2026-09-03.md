### 2. 迭代功能总结

#### **核心功能概述**
本次更新的核心在于**重构了 OpenAI 兼容接口的请求分发机制**。通过引入 Servlet 过滤器（Filter）在进入 Controller 之前拦截请求，根据 JSON Payload 中的 `stream` 标志位强制修改 `Accept` 头。这种做法巧妙地解决了 OpenAI API 标准中“同一个 URL 根据 Body 内容决定响应格式”与 Spring MVC 标准“基于 Header 内容协商”之间的矛盾。

#### **修复的 Bug 汇总**
*   **类型解析异常修复**：此前 Controller 返回 `Object` 类型，在发生异步错误（如 Rate Limit）时，Spring MVC 的异常处理机制无法推断原始响应类型，导致返回 `ResolvableType$EmptyType` 错误。通过拆分方法并指定具体的返回类型（`Flux<ServerSentEvent>` 和 `ResponseEntity`），彻底解决了此问题。

#### **整体影响范围评估**
*   **API 稳定性**：显著提升，特别是异常场景下的响应格式变得可预期。
*   **架构清晰度**：Controller 逻辑更加内聚，职责分离（Stream vs Sync）。
*   **性能影响**：Filter 中存在一次 `readAllBytes()` 操作，对于超大 Body 请求会有轻微内存压力，但对于典型的 Chat 请求（通常几 KB）影响忽略不计。

1.  **内存风险**：`ChatCompletionsStreamRoutingFilter` 中使用了 `request.getInputStream().readAllBytes()`。如果恶意攻击者发送超大的 JSON Body，可能会导致 OOM（内存溢出）。
    *   *优化建议*：建议在读取前检查 `Content-Length`，或者设置一个最大读取限制。

    *   *风险点*：目前市面上并无 gpt-5.4 模型，这可能是一个占位符或内部特定逻辑。建议将其配置化（通过 `@Value` 或配置类读取）。
3.  **依赖风险**：Filter 中直接使用了 `com.alibaba.fastjson.JSONObject`。
    *   *优化建议*：考虑到项目中已经有 Spring 环境，建议优先使用 `Jackson` (ObjectMapper)，以保持序列化库的一致性并减少潜在的安全漏洞风险。

1.  **SQL 代码冗余**：`HomeMapper.xml` 中新增的导出 SQL 与原有的分页查询 SQL 逻辑高度重合（仅少了分页参数）。

2.  **硬编码风险**：文件名称（如 "问题数排行"）硬编码在 Service 常量中。

3.  **Controller 参数绑定冗余**：在 `HomeController` 中手动将 `startTime` 和 `endTime` 赋值给 `HomeQuery` 对象。
    *   *建议*：如果 `HomeQuery` 内部已有这两个字段，Spring MVC 的自动参数绑定（Data Binding）通常可以直接处理，无需手动 `if (startTime != null) query.setStartTime(startTime)`。
4.  **全量导出性能隐患**：目前导出是“免分页”的。如果系统运行时间较长，数据量达到数十万级别，一次性 `List<AgentStatDTO> records = homeMapper.tokensRankingExport(query)` 可能会造成瞬时的内存压力。

    *   *风险*：这使得系统与 PostgreSQL 强绑定，若未来需要迁移到 MySQL 或其他数据库，这部分代码需要重写。

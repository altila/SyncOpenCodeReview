### 3. 优劣与风险分析

#### 优势/亮点
1.  **布局感知算法**：在 `PdfParser` 中通过 `yPos` 坐标对文本行和图片进行二次排序，这是处理 PDF 乱序问题的标准优秀实践。
2.  **结构化记忆 Prompt**：`ApplicationLongTermMemoryService` 中定义的 `LONG_TERM_PROMPT` 非常专业，采用了“提取门槛+分类融合规则”的逻辑，能有效防止记忆碎片化。
3.  **解耦设计**：记忆功能通过 `IApplicationLongTermMemoryService` 接口定义，并利用 Spring 的 `@Async` 实现非阻塞调用，符合高并发架构设计原则。
4.  **健壮性处理**：代码中考虑到了模型输出的 `<think>` 标签过滤，体现了对当前主流大模型（如 DeepSeek）输出特性的深度适配。

#### 劣势/风险
1.  **触发机制过于刚性**：记忆更新逻辑为 `count % pageSize == 0`。如果用户删除了一条历史记录，或者在特定临界点，可能导致更新逻辑跳过或重复触发。建议改为基于“未处理记录数”的阈值判断。
2.  **PDF 图片存储压力**：`PdfParser` 会提取所有宽度 > 100px 的图片并上传 OSS。若用户上传大量包含装饰性小图标的 PDF，会导致 OSS 存储空间迅速膨胀。建议增加图片质量压缩或更严格的过滤算法。
3.  **硬编码 Prompt**：长期记忆的 Prompt 硬编码在 Java 类中，不利于后期根据不同模型进行微调。建议将其配置化（存入数据库或配置文件）。
4.  **SQL 索引风险**：在 `V6__long_term_memory.sql` 中，`application_id` 字段在创建索引时使用了 `uuid_ops`，请确保生产环境数据库插件支持该操作符，否则可能导致迁移失败。
5.  **并发冲突**：虽然使用了异步，但在极短时间内连续触发记忆保存时，`updateById` 可能会产生竞态条件。虽然有唯一索引约束，但建议增加简单的乐观锁或分布式锁。

**架构师建议**：后续可以考虑引入向量数据库来存储这些“长期记忆片段”，实现更精准的记忆检索，而不仅仅是注入到 System Message 中。

### 3. 优劣与风险分析

#### 优势/亮点
1.  **架构解耦（高分项）**：`UserContext` 的引入是典型的架构优化实践。它不仅解决了单元测试难的问题，还为未来可能更换安全框架（如 Spring Security）打下了基础。
2.  **职责单一化**：将 `ApplicationService` 这个“大类”拆分为 Speech、Prompt、Embed 等专项服务，符合单一职责原则，降低了维护成本。
3.  **防御性编程**：在 `ModelConfig.from()` 中实现了健壮的类型转换逻辑，有效防止了 JSON 反序列化后 Map 与实体类混淆导致的崩溃。
4.  **测试覆盖**：新增了 `ThreadLocalUserContextTest`，确保了核心身份上下文逻辑的正确性。

#### 劣势/风险
1.  **技术债务（角色模型）**：将角色从 `Set` 改为 `String` 虽然简化了逻辑，但如果系统未来需要支持“单用户多角色”，此处将面临二次重构。
2.  **工作流兼容性风险**：工作流节点参数（如 `modelIdType`）的变更可能导致旧版本导出的工作流 JSON 在导入新版本时失效，建议增加版本迁移脚本或默认值处理。
3.  **Shell 工具安全隐患**：引入 `ShellSkills` 允许 AI 执行系统命令，这具有极高的安全风险。必须确保该功能在生产环境中默认关闭，或有极其严格的权限审计和沙箱环境。
4.  **依赖复杂度**：LangChain4j 及其实验性组件的引入增加了项目的依赖体积和学习成本，需关注其 API 的稳定性。

**建议**：下一步应重点关注 `ShellSkills` 的安全沙箱实现，并为工作流节点的参数变更编写自动化迁移测试用例。
